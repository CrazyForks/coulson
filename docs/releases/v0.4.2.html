Coulson 0.4.2

August 7, 2026
New
  • Per-app trusted_forwarded_hosts in .coulson.toml — honor x-forwarded-host from an allowlisted upstream proxy on tunnel ingress, re-read per request tunnel
  • coulson env now reports whether each resolved variable is app scope (injected into the process) or coulson scope (consumed by Coulson itself) cli
  • coulson ps gained a process type column cli
Fixed
  • Launch agents now carry AssociatedBundleIdentifiers, so macOS attributes background items to Coulson instead of listing them as anonymous login items macos
  • Orphaned processes are reaped when their app is removed process
  • Lifecycle invariants for delete, scan and process cleanup — app ids are never reused, deletion and spawn are serialized under the process-manager lock, and a spawn revalidates its app row before committing process
  • Row existence and filesystem entries are now settled in a single transaction, so a concurrent scan can no longer resurrect a deleted app or prune a live one core
  • Lifecycle hooks fire from the app row snapshot the process was started with, so app_stop stays complete even after the row is gone hooks
  • Forwarded-host authority is validated before use tunnel
  • .coulsonrc now overrides .coulson.toml for COULSON_MANAGED_SERVICES, matching the general env precedence process
Changed
  • Store runs in WAL mode with a dedicated read connection — read-only queries no longer queue behind scan write transactions core
  • Hooks are stored on the app row instead of a separate in-memory registry, removing a source of drift between the two hooks
